# 단계: 검증

기능: $FEATURE

## 출력 (이 파일 하나만 쓴다)
`$WORK/VERIFY.md`

## 입력 (읽기만 — DESIGN.md·IMPL.md는 절대 수정 금지)
- `$WORK/DESIGN.md` — "검증 기준" 섹션이 테스트의 근거다
- `$WORK/IMPL.md` — 실제 구현 내용

## 할 일
1. DESIGN.md 검증 기준 중 **자동 검증** 층을 `flutter test`로 실행 가능한 테스트로 옮긴다. 테스트 파일은 `$ROOT/test/` 아래 `*_test.dart`로 작성한다.
2. **실기기 수동 검증** 층은 테스트로 만들지 말고, VERIFY.md에 사람용 체크리스트로 그대로 옮겨 적는다.
3. `$WORK/VERIFY.md` 에 기록한다.

## 이 프로젝트의 주의점
- `test/fake-claude`, `test/run-tests.sh`는 파이프라인 하네스 파일이다. 건드리지 말고, Dart 테스트와 무관하다.
- 구현 코드(`lib/`)를 수정하지 않는다. 구현이 틀렸으면 테스트를 느슨하게 만들지 말고 STATUS: BLOCKED.

## VERIFY.md 필수 섹션
- STATUS 라인 (첫 줄)
- 작성한 테스트 파일과 케이스 목록
- 검증 기준 ↔ 테스트 케이스 대응표 (빠진 기준이 있으면 명시)
- 테스트로 덮지 못한 부분 (실기기 수동 체크리스트 포함)

## 중요
테스트 통과 여부는 이 세션이 판정하지 않는다. 파이프라인이 `flutter analyze && flutter test`를 별도로 실행한다.
"통과할 것으로 보인다" 같은 문장을 쓰지 마라. 실제로 실행한 명령과 출력만 기록한다.
