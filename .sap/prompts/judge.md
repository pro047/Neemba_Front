### 확인 수단
- `HANDOFF.json` (저장소 루트) — 감사 세션 핸드오프. `permanent.mines` 에 지뢰,
  `permanent.server_facts` 에 서버 실제 동작, `permanent.decisions` 에 결정 이력이 있다.
  **이것도 주장이다** — `meta.note` 가 "줄번호·개수는 기록 시점 기준" 이라고 못박고 있으므로,
  여기 적힌 값을 근거로 쓸 때는 파일을 직접 열어 재확인한 뒤 `코드확인` 으로 올린다.
  재확인 없이 인용하면 등급은 `추정` 이다.
- `flutter analyze` — 설계가 "이 API 는 이렇게 부른다" 고 주장할 때.
- `flutter test` — 설계가 "이건 이미 테스트로 덮인다" 고 주장하면 그 테스트 파일을 열어
  실제로 그 경로를 타는지 확인한다.
- `git log -S<문자열>` / `git log -p <파일>` — "예전에 이렇게 고쳤다" 류 주장의 확인.
- Flutter SDK 소스 (읽기 전용으로 열려 있음) — 프레임워크 동작 주장의 확인.

### 이 저장소에서 특히 자주 틀리는 주장
- **"riverpod 이 이렇게 동작한다"** — `flutter_riverpod` 3.0.0-dev.17 프리릴리스다. 정식판 문서를
  근거로 쓴 주장은 전부 `추정` 이다. 이 저장소의 기존 사용 패턴을 열어봐야 `코드확인` 이다.
- **"이 경로는 실기기에서 검증됐다"** — HANDOFF.json 의 task 상태에 "실기기 미검증" 이 붙은
  항목이 있다. 커밋·병합됐다는 것과 기기에서 확인됐다는 것은 다르다.
- **"X 가 없다"** — `lib/` 전체를 봐야 한다. 탭이 MIC/RTMP 둘이라 한쪽만 보고 "없다" 고
  쓰는 실패가 실제로 나왔다.
